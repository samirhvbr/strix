# Fork SHVIA do Strix

Fork de [`usestrix/strix`](https://github.com/usestrix/strix) mantido em
[`samirhvbr/strix`](https://github.com/samirhvbr/strix). Este arquivo rastreia a
**nossa** evolução versus a do upstream.

## Version

The fork has its own `X.Y.Z`, independent of upstream's number: `Z` is one delivery, `Y` a new
upstream release (or a structural change of ours), `X` a stable release. The upstream release the
fork sits on is recorded apart, in the "Upstream base" column below.

The current version lives in [`.fork-version`](.fork-version). We do not touch the `version` field
of `pyproject.toml` (it would conflict on every upstream merge).

The rules (when each part bumps, tags `shvia-vX.Y.Z`, Release titles, commit format) and the map
from the old `<upstream>+shvia.<n>` names are in [`version.md`](version.md). Rows below carry both
names; text inside a row keeps the wording of its time, so a `shvia.N` there is the old name.

## Modelo de branches

| Branch        | Papel                                                                 |
|---------------|-----------------------------------------------------------------------|
| `master`      | **Nossa branch principal** (default do fork). Todas as features entram aqui. |
| `main`        | **Espelho do upstream.** Só recebe sync do upstream; base para PRs upstream. |
| `feat/*`      | Feature nossa → sai de `master` → volta para `master`.                 |
| `fix/*`       | Correção destinada ao upstream → sai de `main` (limpo) → PR para o upstream. |

**Sincronizar com o upstream:**

```bash
git fetch upstream
git checkout main && git merge --ff-only upstream/main
git push origin main                         # publish the mirror; skipping this left origin/main 74 commits behind
git checkout master && git merge main        # traz a evolução deles para a nossa linha
```
